SportsAdminService

Owns the full administrative CRUD slice for Sport records. Used exclusively by Admin/SportsController so that controller remains a thin HTTP orchestrator with no ORM access of its own.

Config-management operations (configs, editConfigs, addConfig, deleteConfig, resetConfigs) continue to delegate to SportConfigAdminService and are NOT duplicated here.

Responsibilities:

  • Return index data (sports with Teams for record-count display).
  • Provide the view entity (sport + Teams + formatted configs).
  • Process add/edit/delete/bulk-delete form submissions.
  • Handle the popup ajax-add flow, returning a structured response.

Notes:

  • Keep HTTP concerns (Flash, redirect, allowMethod) in the controller.
  • Returned array keys are relied on by the controller and tests — do not rename them without updating call sites.
  • ajaxAdd response keys ('success', 'message', 'newOption') must stay stable for frontend JS compatibility.
